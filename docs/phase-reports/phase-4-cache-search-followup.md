# Phase 4 followup：相關新聞相似度門檻

## 背景

階段 4 驗證「相關新聞」時 DB 裡只有 1-5 篇 `ENRICHED` 文章，資料太少看不出問題。階段 7 用手機實測、後來把全部 70 篇文章都跑完 enrichment 之後，人工檢查 `/related` 的相似度分數，發現一個沒被規格定義、但實測會出問題的情況：

`SearchService.related()` 原本的邏輯是「不管候選文章實際上有多不相關，都硬湊出 `limit` 篇最接近的」。對有真正相關新聞群聚的文章（例如同一個「黃仁勳回歸輝達」新聞事件的多篇報導）這沒問題，相似度都在 0.8 以上。但對資料集裡比較獨特、沒有真正相關對象的文章（例如一篇健康類的「帕金森氏症神波刀治療」），最接近的 3 篇候選其實是完全不相關的政治類「候選人掃街拜票」新聞，相似度只有 0.52-0.54，卡片上顯示出來會很奇怪、對面試官來說觀感不好。

## 修法

`app/search/service.py` 的 `related()` 查詢加一個 `WHERE dist <= (1 - settings.related_min_similarity)` 條件（等同「相似度 >= 門檻」），`app/config.py` 新增 `related_min_similarity: float = 0.6`。低於門檻的候選直接被排除，`/related` 寧可回傳少於 `limit` 篇、甚至 0 篇，也不會硬湊不相關的內容。

PRD 沒有規定這個門檻值該是多少，`0.6` 是跟使用者討論後依照實測結果（真相關的群聚都在 0.6 以上、明顯不相關的都在 0.55 以下）選的經驗值，不是 PRD 既定規格。

## 驗證結果

用 70 篇全部跑完 enrichment 的真實資料，對 7 篇不同分類的樣本文章跑 `related()` 比較前後差異：

| 文章 | 加門檻前 | 加門檻後 |
| --- | --- | --- |
| #5（財經，川普/波音） | 3 篇，相似度 0.61-0.64 | 不變（3 篇） |
| #15（國際，加州洪患） | 3 篇，相似度 0.55-0.61 | 降為 1 篇（濾掉 2 篇弱相關） |
| #25（財經，巴西幣貶值） | 3 篇，相似度 0.53-0.57 | **0 篇**（全部濾掉） |
| #35（健康，帕金森氏症） | 3 篇（政治類，完全不相關），相似度 0.52-0.54 | **0 篇**（全部濾掉，這是本次要修的主要案例） |
| #45（科技，電腦規格） | 3 篇，相似度 0.54-0.55 | **0 篇**（全部濾掉） |
| #55（科技，黃仁勳回歸） | 3 篇，相似度 0.80-0.84 | 不變（3 篇） |
| #65（政治，蔣萬安） | 3 篇，相似度 0.62-0.71 | 不變（3 篇） |

`uv run ruff check .` 跟 `uv run pytest` 結果跟階段 7 結束時一致（2 個已知 `BLE001`、0 個測試），沒有新增問題。

## 已知問題 / 後續事項

- `0.6` 是經驗值，不是從統計分析嚴謹推導出來的，之後資料量變大（ingestion 持續跑）可能需要重新調整。
- 目前沒有把這個門檻值寫進 PRD 文件本身，只記錄在這份報告跟程式碼註解裡；如果之後要讓這份 PRD 繼續當作「規格真實來源」，可以考慮回頭補一筆。
